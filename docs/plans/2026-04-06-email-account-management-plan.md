# 邮箱账号管理系统实施计划

**文档状态：** 已实现版本回顾，内容已按当前代码现状更新，用于后续继续开发时快速对齐背景。

**目标：** 构建一个仅供单管理员使用的邮箱账号管理后台，支持用户名密码登录、按 `free / plus` 分流的列表管理、搜索筛选分页、新增编辑、软删除、系统单值配置，以及内部导入接口。

**架构：** 前端采用 Next.js App Router 实现登录页与后台列表页，服务端通过 Next.js Route Handler 处理登录校验、业务写入与内部导入。数据库使用 Supabase PostgreSQL，管理员账号预置在数据库中，邮箱账号数据通过软删除保留历史记录。

**技术栈：** Next.js、React、TypeScript、Supabase PostgreSQL、Vercel

---

## 一、需求范围确认

### 已确认需求

- 系统仅有 1 个管理员使用
- 登录方式为用户名 + 密码
- 没有注册页
- 管理员账号由数据库预置
- 主页面为邮箱账号列表页
- 首页默认显示 `free`，可切换 `plus`
- 支持搜索、筛选、分页
- 支持新增、编辑、软删除
- 新增与编辑使用弹窗表单
- 支持动态域名筛选与域名自动回填
- 支持顶部统计卡片
- 支持全局人民币数值配置
- 支持内部 iCloud HME 导入接口
- 数据库使用 Supabase
- 项目部署到 Vercel
- 代码托管到 GitHub

### 暂不纳入第一版

- 多管理员与角色权限
- 找回密码
- Excel 导出
- 物理删除
- 审计日志

## 二、数据模型设计

### 表 1：管理员表 `admin_users`

建议字段：

- `id`：UUID，主键
- `username`：文本，唯一，管理员用户名
- `password_hash`：文本，管理员密码哈希
- `created_at`：时间戳，创建时间
- `updated_at`：时间戳，更新时间

约束建议：

- `username` 设置唯一索引
- 密码只保存哈希，不保存明文

### 表 2：邮箱账号表 `email_accounts`

当前字段：

- `id`：UUID，主键
- `email_name`：文本，邮箱账号名称
- `source`：文本，可空，记录来源
- `is_plus`：布尔，区分 `free / plus`
- `user_name`：文本，用户姓名，可空
- `birthday`：日期，用户生日
- `registered_at`：时间戳，注册时间，可空
- `registered_location`：文本，注册地点，可空
- `is_registered_cg`：布尔，是否注册 `cg`
- `cg_registered_at`：时间戳，可空，`cg` 注册时间
- `is_linked_s2a`：布尔，是否关联 s2a
- `linked_at`：时间戳，可空，关联时间
- `is_expired`：布尔，是否已失效
- `expired_at`：时间戳，可空，失效时间
- `deleted_at`：时间戳，可空，软删除时间
- `created_at`：时间戳，创建时间
- `updated_at`：时间戳，更新时间

字段规则：

- `birthday` 只保存日期
- `registered_at` 在前端按日期输入，但写库时会补当前 UTC 时分
- `linked_at`、`expired_at`、`cg_registered_at` 按日期输入并按零点写入，避免时区偏移
- `is_linked_s2a = false` 时，`linked_at` 必须为空
- `is_registered_cg = false` 时，`cg_registered_at` 必须为空
- `is_expired = false` 时，`expired_at` 必须为空
- 软删除通过 `deleted_at` 标记，默认列表不返回已删除记录
- 当前仅 `email_name` 为必填字段，其他业务字段允许为空

### 表 3：系统设置表 `system_settings`

- `id`：固定为 `1` 的单例主键
- `cny_price`：人民币数值，保留两位小数
- `updated_at`：更新时间

## 三、页面与交互设计

### 页面 1：登录页 `/login`

元素：

- 用户名输入框
- 密码输入框
- 登录按钮
- 登录失败提示

行为：

- 输入用户名和密码后提交
- 后端校验数据库中的管理员账号
- 校验成功后写入会话并跳转到后台首页
- 校验失败显示错误信息

### 页面 2：后台首页 `/dashboard`

区域划分：

- 顶部统计与操作区
- 搜索与筛选区
- 表格区
- 分页区

顶部统计与操作区：

- 页面标题
- 当前管理员信息
- 人民币数值展示与编辑入口
- `free / plus` 类型切换
- 退出登录按钮
- 新增按钮
- 统计卡片：
  - 未关联数量
  - 已关联数量
  - 失效邮箱占比
  - 关联邮箱平均存活时长

搜索与筛选区：

- 搜索关键词
  - 支持按邮箱账号名称搜索
  - 支持按用户姓名搜索
- 域名多选筛选
- `是否关联 s2a` 筛选
- `是否已失效` 筛选

首页列表当前显示列：

1. 邮箱账号名称
2. 注册时间
3. 注册时长
4. 注册地点
5. 是否关联 s2a
6. 关联时间
7. 操作

补充行为：

- 邮箱账号名称带复制按钮
- 邮箱名称颜色会根据业务状态变化
- 列表、统计、域名下拉、分页均按当前 `free / plus` 类型隔离

分页：

- 当前固定每页 10 条
- 支持首页、上一页、下一页、尾页与页码跳转

### 弹窗表单

表单字段：

- 邮箱类型（`free / plus`）
- 邮箱账号名称
- 邮箱域名
- 自定义域名
- 来源
- 用户姓名
- 用户生日
- 注册时间
- 注册地点
- 是否注册 `cg`
- `cg` 注册时间
- 是否关联 s2a
- 关联时间
- 是否已失效
- 失效时间

交互规则：

- 新增与编辑复用同一套表单
- 提交时必须明确选择邮箱类型
- 前端将邮箱输入拆成“账号名 + 域名”两部分，写库时再合并为 `email_name`
- 域名下拉按当前类型从有效记录动态聚合
- 选择“自定义”时允许输入新域名
- 粘贴完整邮箱时会自动拆分账号名与域名
- 勾选“是否注册 cg”后才允许填写 `cg` 注册时间
- 勾选“是否关联 s2a”后才允许填写关联时间
- 勾选“是否已失效”后才允许填写失效时间
- 提交前进行基础校验

## 四、接口与业务规则

### 登录相关

- `POST /api/login`
  - 输入：`username`、`password`
  - 行为：查询 `admin_users`，对密码做哈希比对
  - 成功：写入登录态
  - 失败：返回错误提示

- `POST /api/logout`
  - 清除登录态

- 页面访问保护
  - 未登录访问 `/dashboard` 时跳转到 `/login`

### 邮箱账号相关

- `GET /api/email-accounts`
  - 支持分页
  - 支持关键词搜索
  - 支持 `free / plus` 类型隔离
  - 支持域名筛选
  - 支持布尔筛选
  - 默认只返回 `deleted_at is null` 的记录

- `POST /api/email-accounts`
  - 新增一条邮箱账号记录

- `PATCH /api/email-accounts/:id`
  - 更新一条邮箱账号记录

- `DELETE /api/email-accounts/:id`
  - 实际执行软删除
  - 将 `deleted_at` 更新为当前时间

### 系统设置相关

- `GET /api/system-settings/cny-price`
  - 返回全局人民币数值

- `PATCH /api/system-settings/cny-price`
  - 更新全局人民币数值
  - 自动保留两位小数

### 内部导入相关

- `POST /api/internal/hme-ingest`
  - 通过 Bearer Token 调用
  - 用于导入 iCloud HME 邮箱
  - 重复邮箱不重复插入
  - 默认写入 `free` 类型
  - 默认来源为 `icloud-hme-userscript`

### 校验规则

- 邮箱账号名称不能为空
- 邮箱类型不能为空
- 其余业务字段当前允许为空
- 自定义域名模式下，自定义域名不能为空
- 未注册 `cg` 时禁止保留 `cg_registered_at`
- 未关联时禁止提交关联时间
- 未失效时禁止提交失效时间
- 删除默认采用软删除
- 管理员密码只允许保存哈希，不允许明文存储

当前已完成的主线能力：

## 七、关于 AGENTS.md 的建议

`AGENTS.md` 适合保存“长期稳定、对后续所有对话都有效”的协作规则，不适合保存容易变化的产品需求、账号信息或部署密钥。

适合写入 `AGENTS.md` 的内容：

- 固定使用中文回复
- 非代码文档使用中文
- 代码注释使用中文
- 优先使用的技术栈约定
- 仓库目录约定
- 常见命令约定
- 提交规范

不建议写入 `AGENTS.md` 的内容：

- 管理员用户名和密码
- Supabase 密钥
- Vercel 密钥
- 这次项目的临时需求细节
- 将来可能变化的字段规则

更合适的做法：

- 把协作规范放到 `AGENTS.md`
- 把项目需求与方案放到 `docs/plans/` 或 `docs/`
- 把环境变量放到 `.env.local`
- 把建表 SQL 放到 `supabase/`

如果后续你担心换对话丢上下文，最值得尽早沉淀的是：

1. `AGENTS.md` 里的仓库级协作规则
2. `docs/plans/` 里的实施计划
3. `README.md` 里的项目启动方式
